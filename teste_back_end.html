Plano de Testes

plano de teste é um documento que especifica, principalmente:

  • o objetivo do teste;
  • o escopo do sistema e os requisitos que deverão ser avaliados;
  • oselementos que serão testados e quais dados serão monitorados durante a execução do teste;
  • o cronograma de atividades;
  • a técnica que será utilizada (funcional, estrutural etc);
  • s recursos que serão utilizados (tipo de software).

Caso de teste

um caso de teste pode ser agrupado com outros casos para formar uma suíte de testes. Por exemplo:

  • caso de teste 1: efetuar login;
  • caso de teste 2: Incluir novos produtos;
  • caso de teste 3:finaliar compra;
  • caso de teste 4: efetuar logout.

Relatório de Incidentes de Testes

é um documento ou registro essencial que detalha falhas, erros ou comportamentos inesperados encontrados na camada de lógica do sistema (APIs, bancos de dados, integrações, regras de negócio) durante o ciclo de QA (Quality Assurance).Diferente do frontend, os incidentes de backend geralmente envolvem mensagens de erro em APIs, códigos de status HTTP incorretos, problemas de performance, corrupção de dados ou falhas de segurança.

Relatório de Resumo de Teste

é um documento técnico e estratégico que consolida os resultados, métricas e conclusões obtidos após a execução dos testes na camada de aplicação, banco de dados, APIs e integrações. Diferente do front-end (onde o foco é a interface e a experiência do usuário), o resumo de teste back-end foca em estabilidade, segurança performance, integridade dos dados e regras de negócio.

Elaboração do caso de Teste

Trata-se do documento que define comounidades que serão testadas, incluindo dados de entrada, resultados, ações e condições gerais para a execução do teste, ou seja, responda à pergunta: o que será testado? Uma resposta poderia ser caso de teste 1: efetuar login.

Exemplo prático: Tela de Login Cenário 1: Login com sucesso • ID: CT_LOGIN_01
• Objetivo: Verificar se o usuário consegue acessar o sistema com credenciais válidas.
• Pré-condições:
• O usuário já possui cadastro ativo no sistema.
• Estar na tela de login.
• Passos:
1. Digitar o e-mail usuario@email.com no campo "E-mail".
2. Digitar a senha Senha123! no campo "Senha".
3. Clicar no botão "Entrar".
• Resultado esperado:
• O sistema autentica o usuário e redireciona para a página principal (Dashboard), exibindo a mensagem de boas-vindas.

Execução do Programa

Nessa etapa, execute-se o programa ou o código utilizando os atributos do HTML, como classe, id, título, texto, de acordo com o plano de teste e com os casos de testes elaborados, objetivando identificar os elementos da página são semelhantes às interações do usuário. É por meio dessa interação que é possível obter os resultados e a coleta de erros.

Monitoração e Controle

Durante a execução do teste, os dados são monitorados e selecionados aleatoriamente. fatores que influenciam o erro. Como resultado dessa etapa, sugere-se a elaboração de um documento chamado relatório de incidente de teste, que deve descrever todos os eventos ocorridos, viabilizando, posteriormente, a análise pela equipe de desenvolvimento, responsável por realizar a correção dessas falhas.

Avaliação de Resultados

Nessa etapa, um equipe de desenvolvimento avaliará o erro, buscando compreender o que o ocasionou, por exemplo erro de sistema, de código, de internet, de hardware, para, assim, corrige-lo. É normal que as aplicações sejam apresentadas erros de modo não consecutivo. Alguns fatores motivadores da ocorrência de erros, como rede, requisições ou caso o sistema está consumindo uma API que está fora do ar por razões de atualização, de implantação do sistema ou do serviço do site em que o sistema está hospedado ou, ainda, em razão de uma atualização ou correção de erro no site que está no ambiente de produção.

Comunicação com as Equipes de Automoção de Testes

Uma equipe de automação de testes é responsável por desenvolver um encontrei que testará o aplicativo, o serviço ou o sistema online. Não planejamento de testes, cada equipe se responsabiliza por uma atividade, por exemplo, criar um -, Monitorar o teste, fazer a coleta dos erros etc.
